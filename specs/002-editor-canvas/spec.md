# Feature Specification: 階段 1（上）：非破壞式編輯與畫布介面

**Feature Branch**: `002-editor-canvas`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "階段 1（第一部分）：非破壞式編輯核心與畫布介面。新增 packages/editor：可序列化的編輯文件模型（原圖不變，編輯為操作清單：裁切、旋轉 90°、翻轉、調整尺寸），復原/重做，以 Canvas2D 算繪（同一套算繪可在 Worker 匯出時使用）；apps/web 改為以畫布為中心的介面：拖入或貼上後顯示畫布，裁切框可拖曳與鍵盤調整、常用比例；工具列與快捷鍵（C 裁切、R 旋轉、⌘Z/⌘⇧Z、⌘C 複製結果）；前後對比滑桿；編輯後的結果再交給既有的壓縮核心壓到目標大小。「壓縮後上傳」流程從貼上到拿到結果最多 2 個操作。註解工具（畫筆、箭頭、文字、馬賽克等）屬於下一個 spec（003），本 spec 範圍外。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 貼上就拿到結果：兩個操作完成「壓縮後上傳」 (Priority: P1)

使用者貼上（或拖入）一張圖，畫面立刻以畫布呈現圖片，並在背景自動壓到目標大小。
使用者按下 ⌘C／Ctrl+C（焦點不在文字欄位時），壓縮後的結果就進入剪貼簿。從貼上到拿到結果只需要兩個操作。

**Why this priority**: 這是 vision 中「壓縮後上傳」這條最短路徑的驗收標準（最多 2 個操作），
也是根公理「消滅摩擦」最直接的體現。新介面必須先保住這條路徑，才談得上編輯。

**Independent Test**: E2E：貼上一張大圖 → 按 ⌘C → 讀回剪貼簿得到 PNG，全程只有兩次使用者輸入。

**Acceptance Scenarios**:

1. **Given** 空白的工作區，**When** 使用者貼上一張 4 MB 照片，**Then** 畫布顯示圖片，壓縮結果與狀態在不需要其他操作的情況下出現。
2. **Given** 已有壓縮結果，且焦點不在任何文字輸入欄位，**When** 使用者按 ⌘C／Ctrl+C，**Then** 結果以圖片寫入剪貼簿，並顯示成功通知。
3. **Given** 焦點在目標大小欄位，**When** 使用者按 ⌘C，**Then** 執行一般的文字複製，不會攔截。
4. **Given** 已有結果，**When** 使用者按 ⌘S／Ctrl+S，**Then** 下載結果（取代瀏覽器的「儲存網頁」）。

---

### User Story 2 - 非破壞式的基本編輯 (Priority: P2)

使用者可以裁切（自由或固定比例）、旋轉 90°、水平或垂直翻轉、調整輸出尺寸。
每次編輯都能復原與重做；原圖永遠保持不變，隨時可以「全部還原」。編輯完成後，結果自動重新壓縮。

**Why this priority**: vision 階段 1 的編輯能力。非破壞式設計是憲章 III 的要求，也讓之後的註解工具（spec 003）
能疊加在同一份文件模型上。

**Independent Test**: 對已知內容的測試圖片套用一連串編輯，檢查匯出結果的尺寸與特定位置的像素顏色；
接著連續復原，確認每一步都回到正確狀態。

**Acceptance Scenarios**:

1. **Given** 一張 400×300 的圖片，**When** 使用者裁切出左上 200×100 的區域，**Then** 匯出結果為 200×100，內容是原圖左上區域。
2. **Given** 一張 400×300 的圖片，**When** 使用者順時針旋轉一次，**Then** 匯出結果為 300×400，原本左上角的像素出現在右上角。
3. **Given** 一張圖片，**When** 使用者水平翻轉，**Then** 原本最左側的像素出現在最右側。
4. **Given** 使用者已依序做了裁切、旋轉、翻轉，**When** 連按三次復原，**Then** 每一步都回到上一個狀態，最後與原圖相同；再按重做可以依序恢復。
5. **Given** 使用者選擇 1:1 比例，**When** 拖曳裁切框的角落，**Then** 裁切框維持正方形。
6. **Given** 使用者把輸出寬度設為 50%，**When** 套用，**Then** 匯出尺寸為原本的一半，並維持比例。
7. **Given** 一連串編輯，**When** 使用者按「全部還原」，**Then** 回到原圖，而且這個動作本身也可以復原。
8. **Given** 編輯後，**When** 壓縮完成，**Then** 壓縮結果反映了編輯（例如尺寸與方向正確）。

### User Story 3 - 前後對比與鍵盤優先的操作 (Priority: P3)

使用者可以用一條對比滑桿，在同一個畫面上比較「編輯後、未壓縮」與「編輯並壓縮後」的結果；
所有工具都有快捷鍵與可見的提示，只用鍵盤也能完成全部操作。

**Why this priority**: 讓使用者確認壓縮後畫質是否可接受，並落實憲章 IV 的鍵盤與無障礙要求。

**Independent Test**: 只用鍵盤完成「放入 → 裁切 → 旋轉 → 復原 → 對比 → 複製」；自動化無障礙檢查零違規。

**Acceptance Scenarios**:

1. **Given** 已有結果，**When** 使用者拖曳或用方向鍵移動對比滑桿，**Then** 滑桿左側顯示未壓縮的畫面、右側顯示壓縮後的結果，且滑桿有可讀的數值（例如「50%」）。
2. **Given** 畫布有焦點，**When** 使用者按 C，**Then** 進入裁切模式；方向鍵移動裁切框（Shift 加速），Enter 套用，Esc 取消。
3. **Given** 任何狀態，**When** 使用者按 R 或 Shift+R，**Then** 順時針或逆時針旋轉 90°。
4. **Given** 工具列，**When** 使用者把滑鼠移上任一工具或以鍵盤聚焦，**Then** 顯示工具名稱與快捷鍵。
5. **Given** 按下 ?（Shift+/），**When** 快捷鍵說明出現，**Then** 列出所有快捷鍵，Esc 關閉。

---

### Edge Cases

- 裁切框被拖到圖片外：裁切框限制在圖片範圍內；最小 1×1 px。
- 在裁切模式中按復原：先取消進行中的裁切，不會跳過它直接復原前一步。
- 旋轉 4 次：回到原方向，匯出與原圖完全相同。
- 調整尺寸時輸入 0、負數或大於原圖 4 倍：拒絕並提示有效範圍（1 px 到原圖的 400%）。
- 編輯期間又放入新圖：新圖取代目前的文件，舊文件的編輯歷史一併清除（放入動作本身不可復原）。
- 超大圖片（例如 8000×6000）：畫布以縮小的預覽呈現，匯出仍以原圖解析度計算。
- 編輯過程中壓縮仍在進行：新的編輯會取代舊的壓縮請求（沿用階段 0 的取代機制）。
- 按 ⌘C 時壓縮尚未完成：等待結果完成後再寫入剪貼簿，並顯示「處理中」；若失敗則顯示錯誤。

## Requirements *(mandatory)*

### Functional Requirements

**編輯文件**

- **FR-001**: 系統 MUST 以「原圖 + 有序的編輯操作清單」表示一份文件；原圖資料在任何操作下都不可被修改。
- **FR-002**: 文件 MUST 可以序列化與還原，序列化後再還原的文件匯出結果必須與原文件完全相同。
- **FR-003**: 支援的編輯操作：裁切（矩形，座標以當下方向的影像為準）、旋轉 90°（順時針／逆時針）、水平翻轉、垂直翻轉、調整輸出尺寸（像素或百分比，維持比例可切換）。
- **FR-004**: 系統 MUST 提供復原與重做，至少保留 100 步；新的編輯會清除重做堆疊。
- **FR-005**: 「全部還原」MUST 把文件回到原圖狀態，且這個動作本身可以復原。
- **FR-006**: 匯出 MUST 以原圖的完整解析度套用所有編輯，並在不阻塞介面的情況下完成；匯出結果交給既有的壓縮流程壓到目標大小。

**畫布介面**

- **FR-007**: 放入圖片後，畫面 MUST 以畫布為主體顯示目前的編輯狀態；大圖以縮小預覽顯示，編輯操作在預覽上即時反映。
- **FR-008**: 裁切模式 MUST 提供可拖曳的裁切框與八個控制點、比例選項（自由、原始比例、1:1、4:3、3:2、16:9），以及鍵盤操作（方向鍵移動、Shift+方向鍵 10 px、Alt+方向鍵調整大小、Enter 套用、Esc 取消）。
- **FR-009**: 工具列 MUST 包含：裁切、逆時針旋轉、順時針旋轉、水平翻轉、垂直翻轉、調整尺寸、復原、重做、全部還原；每個按鈕有可讀名稱與快捷鍵提示。
- **FR-010**: 快捷鍵：C 裁切、R 順時針旋轉、Shift+R 逆時針旋轉、F 水平翻轉、Shift+F 垂直翻轉、⌘/Ctrl+Z 復原、⌘/Ctrl+Shift+Z 與 Ctrl+Y 重做、⌘/Ctrl+C 複製結果、⌘/Ctrl+S 下載結果、? 顯示快捷鍵說明。焦點在文字輸入欄位時，單鍵快捷鍵與 ⌘C 都不攔截。
- **FR-011**: 系統 MUST 提供前後對比滑桿（編輯後但未壓縮 vs. 編輯並壓縮後的結果；兩者範圍與方向相同，才能看出壓縮對畫質的影響），可用滑鼠、觸控與方向鍵操作，並具備無障礙的數值描述。
- **FR-012**: 每次編輯後 MUST 自動重新壓縮（沿用階段 0 的設定、狀態與誠實回報）；壓縮狀態與結果資訊持續可見。
- **FR-013**: 「壓縮後上傳」路徑：從放入圖片到結果進入剪貼簿或下載，MUST 最多兩個使用者操作（放入、⌘C 或 ⌘S）。
- **FR-014**: 介面 MUST 維持階段 0 的要求：淺色／暗色模式、360 px 寬可完整操作、觸控可操作裁切框、所有互動元素可用鍵盤操作、自動化無障礙檢查零違規。

### Key Entities

- **編輯文件**：原圖（不可變）、操作清單、目前在清單中的位置（供復原／重做）。
- **編輯操作**：類型（裁切、旋轉、翻轉、調整尺寸、全部還原）與參數；每個操作都是純資料、可序列化。
- **文件狀態（衍生）**：由原圖依序套用操作得出的目前尺寸與方向；用來顯示預覽、限制裁切框與計算匯出。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「壓縮後上傳」流程從放入到結果進入剪貼簿只需要 2 個使用者操作，由端對端測試驗證。
- **SC-002**: 裁切、旋轉、翻轉、調整尺寸的匯出結果，在測試圖片上的尺寸與指定位置像素 100% 正確。
- **SC-003**: 任意 50 步以內的編輯序列，全部復原後與原圖完全一致，全部重做後與最終狀態完全一致。
- **SC-004**: 在 12 百萬像素的圖片上，每次編輯後畫布預覽在 100 ms 內更新，拖曳裁切框時畫面跟手。
- **SC-005**: 只用鍵盤可以完成「放入 → 裁切 → 旋轉 → 復原 → 對比 → 複製」整個流程；自動化無障礙檢查零違規（淺色與暗色）。
- **SC-006**: 首次載入所需的程式碼仍不超過 200 KB（壓縮後）。
- **SC-007**: 12 百萬像素以下的照片，編輯後到看到新的壓縮結果不超過 3 秒。

## Assumptions

- 畫布函式庫：不採用 Konva 或 Fabric，改用自建的文件模型 + Canvas2D 算繪 + SVG 互動層；理由與替代方案在 plan 的 research 記錄（vision「未決」項的決定）。
- 匯出在 Worker 中進行，與階段 0 的壓縮流程串接；預覽在主執行緒以縮小的影像算繪。
- 調整尺寸只做縮放；任意角度旋轉、透視修正不在本 spec 範圍。
- 「放入新圖」不可復原；這是刻意的簡化（避免同時保留兩份大圖的記憶體）。
- 不做跨工作階段的保存（重新整理頁面即清除），符合「圖片不離開裝置」且不寫入任何儲存空間。
- 元件測試：依 draft「元件測試的適用範圍」的推薦，本 spec 起引入元件層級的測試（文件模型與互動元件）。
- 範圍外：註解工具（spec 003）、外掛（階段 2）、PWA 與批次（階段 3）。
