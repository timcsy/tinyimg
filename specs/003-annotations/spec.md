**Feature Branch**: `003-annotations`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 貼上、標註、複製 (Priority: P1)

使用者貼上一張截圖，用箭頭指出重點、用方框圈出區域、寫上簡短文字，然後按 ⌘C，
把標註好的圖貼到 Slack 或文件裡。

**Why this priority**: 這是 vision 的「標註後分享」路徑，也是階段 1 尚未完成的成功標準（「貼上 → 標註 → 複製」有 E2E）。

**Independent Test**: E2E：貼上截圖 → 畫一個箭頭、一個矩形、一段文字 → ⌘C；剪貼簿的圖片在對應位置確實出現註解的顏色。

**Acceptance Scenarios**:

1. **Given** 已放入圖片，**When** 使用者選擇箭頭工具並在畫布上從 A 拖到 B，**Then** 出現一個從 A 指向 B 的箭頭，並自動重新壓縮。
2. **Given** 已有註解，**When** 使用者按 ⌘C，**Then** 剪貼簿中的圖片包含這些註解。
3. **Given** 使用者選擇文字工具並點擊畫布，**When** 輸入文字並按 Enter（或點擊別處），**Then** 文字出現在點擊的位置；按 Esc 則取消。
4. **Given** 使用者選擇編號工具，**When** 依序點擊三個位置，**Then** 出現編號 1、2、3 的圓形標記；刪除 2 之後，原本的 3 自動變成 2。

---

### User Story 2 - 遮掉敏感資訊（馬賽克） (Priority: P2)

使用者在截圖上框出 Email、電話或臉部，套用馬賽克後再分享。

**Why this priority**: 隱私是本產品的核心承諾（原則 1）。馬賽克如果只是視覺上的遮蓋、而原始像素仍可被還原，會造成使用者以為安全、其實洩漏的後果（原則 2「誠實」）。

**Independent Test**: 對一張已知內容的圖片在某區域套用馬賽克，匯出後檢查：該區域內每個方塊只剩單一顏色，且與原始像素不同；區域外的像素完全不變。

**Acceptance Scenarios**:

1. **Given** 已放入圖片，**When** 使用者用馬賽克工具框選一個區域，**Then** 該區域顯示為明顯的方塊化，且匯出結果中該區域的原始細節無法辨識或還原。
2. **Given** 馬賽克區域，**When** 使用者裁切或旋轉圖片，**Then** 馬賽克仍覆蓋原本的內容（跟著影像走）。
3. **Given** 馬賽克已套用，**When** 使用者按復原，**Then** 馬賽克消失（文件層面可復原；匯出的檔案中則永遠是破壞後的像素）。

---

### User Story 3 - 調整與管理註解 (Priority: P3)

使用者可以選取已畫的註解，移動、刪除、修改顏色或粗細；所有註解操作都能復原與重做，且只用鍵盤也能完成。

**Why this priority**: 標註很少一次到位；能修正才不會因為一個失誤而整張重來（根公理「消滅摩擦」）。

**Independent Test**: 畫兩個註解 → 選取其中一個 → 用方向鍵移動 → 改顏色 → 刪除 → 復原三次回到原狀。

**Acceptance Scenarios**:

1. **Given** 已有註解，**When** 使用者用選取工具點擊它（或用 Tab 在註解之間切換），**Then** 它被選取並顯示外框。
2. **Given** 已選取註解，**When** 使用者按方向鍵（Shift 加速）或拖曳，**Then** 註解移動；按 Delete 或 Backspace 則刪除。
3. **Given** 已選取註解，**When** 使用者改變顏色或粗細，**Then** 只有該註解改變，並可復原。
4. **Given** 任何註解操作，**When** 按 ⌘Z／⌘⇧Z，**Then** 依序復原或重做，與 002 的編輯操作共用同一條歷史。

---

### Edge Cases

- 註解畫在裁切範圍外：保留在文件中但不出現在匯出結果；放大裁切範圍或全部還原後又會出現。
- 旋轉或翻轉後再畫註解：新的註解仍落在使用者看到的位置（換算回原圖座標）。
- 調整尺寸（縮小）後：註解跟著縮放，線條粗細也等比例縮放。
- 文字為空就按 Enter：不建立註解。
- 拖曳距離極短（例如誤點）：不建立箭頭、矩形、橢圓或馬賽克（小於 3 px 視為誤觸）。
- 馬賽克與其他註解重疊：馬賽克只破壞原圖像素，不會把其他註解也打碼（其他註解畫在馬賽克之上）。
- 大量註解（例如 200 個）：畫布仍可流暢操作。
- 放入新圖片：清除所有註解（與 002「放入新圖不可復原」一致）。

## Requirements *(mandatory)*

### Functional Requirements

**註解種類**

- **FR-001**: 系統 MUST 提供以下註解：畫筆（自由線條）、螢光筆（半透明粗線，不遮蓋底下內容）、箭頭、矩形、橢圓、文字、編號標記、馬賽克。
- **FR-002**: 畫筆、螢光筆、箭頭、矩形、橢圓 MUST 可設定顏色（至少 8 種預設色，含高對比的紅、黃、藍、綠、黑、白）與粗細（細、中、粗）。
- **FR-003**: 編號標記 MUST 依建立順序自動編號；刪除其中一個時，其後的編號自動遞補。
- **FR-004**: 馬賽克 MUST 在匯出結果中把框選區域的像素以方塊平均色取代（方塊邊長至少 12 px，且至少為區域短邊的 1/20），使原始細節無法辨識；馬賽克只作用於原圖像素，其他註解畫在其上。

**行為**

- **FR-005**: 所有註解 MUST 以資料形式保存（非破壞式）；只有匯出時才合成到影像中。
- **FR-006**: 註解 MUST 以原圖座標保存，因此裁切、旋轉、翻轉、調整尺寸後仍覆蓋相同的影像內容；調整尺寸時線條粗細與文字大小等比例縮放。
- **FR-007**: 使用者 MUST 能選取、移動、刪除註解，並修改已選取註解的顏色與粗細。
- **FR-008**: 新增、移動、刪除、修改註解 MUST 與 002 的編輯操作共用同一條復原／重做歷史。
- **FR-009**: 匯出 MUST 在不阻塞介面的情況下完成合成，再交給既有的壓縮流程。

**操作與無障礙**

- **FR-010**: 工具 MUST 有快捷鍵：V 選取、P 畫筆、H 螢光筆、A 箭頭、B 矩形、E 橢圓、T 文字、N 編號、M 馬賽克、Delete／Backspace 刪除已選取註解、Esc 取消進行中的操作並回到選取工具。002 的 C、R、F 等快捷鍵維持不變。
- **FR-011**: 只用鍵盤 MUST 能建立註解：選擇工具後按 Enter 在畫布中央建立預設大小的註解，再用方向鍵移動、Alt + 方向鍵調整大小；Tab 在既有註解之間切換選取。
- **FR-012**: 每個註解 MUST 對輔助科技有可讀的描述（例如「箭頭 1，紅色」），自動化無障礙檢查零違規（淺色與暗色）。
- **FR-013**: 首次載入所需的程式碼 MUST 仍不超過 200 KB（壓縮後）。

### Key Entities

- **註解**：種類、原圖座標中的幾何（點列、起訖點或矩形）、樣式（顏色、粗細）、文字內容（文字註解）；每個註解有穩定的識別碼。
- **註解操作**：新增、修改（幾何或樣式）、刪除；與 002 的編輯操作一起放在文件歷史中。
- **編號**：由編號標記在清單中的順序衍生，不另外儲存。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「貼上 → 標註（箭頭 + 矩形 + 文字）→ 複製」可在 6 個以內的使用者操作完成，並由端對端測試驗證剪貼簿圖片包含註解。
- **SC-002**: 馬賽克區域在匯出結果中，每個方塊內只剩單一顏色；區域外的像素 100% 不變；以已知內容的測試圖片驗證。
- **SC-003**: 任意 50 步以內混合「編輯 + 註解」的操作序列，全部復原後與原圖完全一致，全部重做後與最終狀態完全一致。
- **SC-004**: 經過裁切、旋轉、翻轉後，註解在匯出結果中覆蓋的影像內容與建立時相同（以測試圖片上的標記點驗證，誤差不超過 1 px，縮放時依比例）。
- **SC-005**: 所有註解工具只用鍵盤即可完成建立、選取、移動、刪除；自動化無障礙檢查零違規。
- **SC-006**: 畫布上有 200 個註解時，拖曳移動註解仍跟手（每次更新不超過 50 ms）。
- **SC-007**: 首次載入程式碼仍不超過 200 KB（壓縮後）。

## Assumptions

- 文字使用系統字型（與介面相同的字體堆疊），大小三段（小、中、大）；不提供自訂字型（範圍外）。
- 箭頭為直線，箭頭頭部大小隨粗細等比例。
- 螢光筆以 40% 不透明度、粗細為一般畫筆的 3 倍呈現。
- 註解不支援旋轉角度（範圍外：自由角度旋轉）；跟隨影像的 90° 旋轉與翻轉則支援。
- 畫筆線條在建立時做輕度平滑化，以減少手抖造成的鋸齒。
- 範圍外：圖層面板、群組、對齊工具、外掛（階段 2）。
