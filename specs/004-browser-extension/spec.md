## User Scenarios & Testing *(mandatory)*

### User Story 1 - 截圖後直接標註 (Priority: P1)

使用者在任何網頁上按下快捷鍵（預設 Ctrl/Cmd+Shift+S）或點擊工具列上的 TinyImg 圖示，目前分頁的可見區域被截取下來，
直接在編輯器中開啟；使用者標註後按 ⌘C，就能貼到 Slack 或文件。

**Why this priority**: 這是外掛相對網頁版最大的價值：省掉「另外截圖 → 存檔 → 開網站 → 上傳」的每一步（根公理「消滅摩擦」、原則 3「工具出現在使用者所在的地方」）。

**Independent Test**: 在測試網頁上觸發截圖命令，編輯器開啟且畫布顯示與分頁相同尺寸的圖片；標註後複製，剪貼簿有圖片。

**Acceptance Scenarios**:

1. **Given** 使用者在一般網頁上，**When** 按下 Ctrl/Cmd+Shift+S，**Then** 編輯器在 2 秒內開啟，畫布顯示目前分頁可見區域的截圖。
2. **Given** 使用者選擇「框選區域截圖」，**When** 在網頁上拖曳出一個矩形，**Then** 編輯器只顯示該區域；按 Esc 則取消且不留下任何痕跡。
3. **Given** 編輯器已開啟截圖，**When** 使用者使用任何網頁版的功能（壓縮、編輯、註解、複製、下載），**Then** 行為與網頁版完全相同。
4. **Given** 使用者在瀏覽器不允許截圖的頁面（例如瀏覽器設定頁、擴充功能商店），**When** 觸發截圖，**Then** 顯示明確訊息說明此頁面無法截圖，不會無聲失敗。

---

### User Story 2 - 右鍵編輯網頁上的圖片 (Priority: P2)

使用者在網頁圖片上按右鍵，選「用 TinyImg 編輯」，那張圖片就在編輯器中開啟。

**Why this priority**: 常見情境是「把網頁上這張圖壓小／標註後轉給別人」；右鍵比下載再上傳少了好幾步。

**Independent Test**: 在測試網頁的圖片上觸發選單命令，編輯器開啟且畫布為該圖片（尺寸一致）。

**Acceptance Scenarios**:

1. **Given** 同網域的圖片，**When** 選「用 TinyImg 編輯」，**Then** 編輯器開啟該圖片。
2. **Given** 其他網域的圖片且使用者尚未授權讀取，**When** 選「用 TinyImg 編輯」，**Then** 先詢問是否允許讀取該網站的圖片；同意後開啟；拒絕則顯示說明，並提示可改用截圖。
3. **Given** 圖片無法讀取（網路錯誤、非圖片），**When** 選單命令執行，**Then** 顯示明確錯誤訊息。

---

### User Story 3 - 以側邊欄開啟並保持在原頁面 (Priority: P3)

使用者可以選擇讓編輯器開在瀏覽器側邊欄，一邊看原網頁一邊標註；也可以開在新分頁。

**Why this priority**: 側邊欄讓使用者不必離開目前的頁面；但空間較小，所以保留新分頁作為選項。

**Independent Test**: 切換開啟方式設定後觸發截圖，編輯器出現在對應位置。

**Acceptance Scenarios**:

1. **Given** 開啟方式為「側邊欄」（預設），**When** 截圖，**Then** 編輯器出現在側邊欄，原分頁保持不變。
2. **Given** 開啟方式為「新分頁」，**When** 截圖，**Then** 編輯器在新分頁開啟並取得焦點。
3. **Given** 側邊欄已開著一張圖片，**When** 再次截圖，**Then** 新圖片取代舊的（與網頁版「放入新圖片」一致），不會開出第二個側邊欄。

---

### User Story 4 - 發佈可安裝的外掛套件 (Priority: P4)

維護者推送版本標記（例如 v0.2.0）後，自動產生外掛的安裝套件，並附在 GitHub Release 上；套件內的版本號與標記一致。

**Why this priority**: 讓外掛可以被安裝與審查，為之後上架商店做準備（上架本身屬於對外動作，不在本範圍）。

**Independent Test**: 在本機以模擬的版本標記執行打包流程，檢查套件內容與版本號。

**Acceptance Scenarios**:

1. **Given** 推送 `v0.2.0` 標記，**When** 發佈流程完成，**Then** GitHub Release 附有 `tinyimg-extension-0.2.0.zip`，其中 manifest 的版本為 `0.2.0`。
2. **Given** 套件內容，**When** 檢查，**Then** 不包含任何遠端程式碼載入、測試檔或原始碼對照檔以外的多餘檔案。

---

### Edge Cases

- 截圖時頁面捲動到中間：只截取可見區域（範圍外：整頁長截圖）。
- 高解析度螢幕（裝置像素比 2 或 3）：截圖保留實際像素，框選座標正確換算。
- 框選極小的區域（小於 4 px）：視為取消。
- 連續快速觸發兩次截圖：只保留最後一次（與網頁版「新的取代舊的」一致），不會出現兩個編輯器或混用兩張圖片。
- 右鍵的圖片是 data URL 或 blob URL：直接讀取，不需要額外權限。
- 右鍵的圖片是 SVG：轉為點陣後開啟。
- 使用者撤銷了之前授權的網站權限：下次右鍵時重新詢問。
- 外掛更新後：已開著的側邊欄可以正常重新載入，不會卡在舊版本。

## Requirements *(mandatory)*

### Functional Requirements

**共用編輯器**

- **FR-001**: 網頁版與外掛 MUST 使用同一份編輯器介面；外掛中的壓縮、編輯、註解、複製、下載行為 MUST 與網頁版一致，並由同一組測試驗證。
- **FR-002**: 抽出共用編輯器後，網頁版的所有既有測試 MUST 不經修改即通過。

**截圖**

- **FR-003**: 使用者 MUST 能以快捷鍵（預設 Ctrl/Cmd+Shift+S，可在瀏覽器的擴充功能快捷鍵設定中修改）或工具列圖示截取目前分頁的可見區域並在編輯器中開啟。
- **FR-004**: 使用者 MUST 能選擇「框選區域截圖」：在頁面上疊一層選取遮罩，拖曳選取範圍後只截取該區域；Esc 取消；遮罩不得改變或殘留在原頁面上。
- **FR-005**: 無法截圖的頁面 MUST 顯示明確的訊息。

**右鍵選單**

- **FR-006**: 在網頁圖片上 MUST 提供「用 TinyImg 編輯」選單項目，開啟該圖片。
- **FR-007**: 讀取其他網域的圖片 MUST 在第一次需要時才請求對應網站的讀取權限；被拒絕時顯示說明並建議改用截圖。

**開啟方式**

- **FR-008**: 編輯器 MUST 可開在側邊欄（預設）或新分頁，由使用者設定；同時只會有一個編輯器實例在處理最新的圖片。

**權限與隱私**

- **FR-009**: 外掛 MUST 只宣告完成功能所需的最小權限；每一項權限的用途 MUST 記錄在文件中（套件內的說明與 repo 的文件）。
- **FR-010**: 外掛 MUST 不載入任何遠端程式碼，不傳送任何圖片或使用資料到任何伺服器。

**發佈**

- **FR-011**: 推送 `v*` 版本標記時 MUST 自動產生外掛安裝套件並附加到 GitHub Release；套件內的版本號 MUST 取自標記。

### Key Entities

- **待開啟的圖片**：來源（可見區域截圖、框選截圖、右鍵圖片）、圖片資料、建立時間；同時只保留最新的一張。
- **外掛設定**：開啟方式（側邊欄／新分頁）。
- **權限紀錄**：已授權讀取的網站（由瀏覽器管理，外掛只查詢與請求）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 從按下快捷鍵到編輯器顯示截圖，不超過 2 秒。
- **SC-002**: 「截圖 → 標註 → 複製」可在 4 個以內的使用者操作完成（快捷鍵、畫一個註解、⌘C），並由端對端測試驗證。
- **SC-003**: 網頁版既有的端對端測試在抽出共用編輯器後 100% 通過，且未經修改。
- **SC-004**: 外掛宣告的必要權限不超過 5 項，且每一項都在文件中有用途說明；主機權限只出現在「可選」清單中。
- **SC-005**: 外掛套件中沒有任何遠端程式碼載入（以自動檢查掃描）。
- **SC-006**: 推送版本標記後，Release 上的套件版本號與標記 100% 一致。
- **SC-007**: 外掛的編輯器頁面通過與網頁版相同的自動化無障礙檢查（零違規）。

## Assumptions

- 目標瀏覽器為 Chrome 與 Edge（同一份 Manifest V3 套件）；Firefox 版屬於階段 3。
- 截圖只涵蓋可見區域；整頁長截圖、錄影不在範圍內。
- 開啟方式預設為側邊欄；側邊欄空間較小時，編輯器使用網頁版已支援的窄版面（360 px 起）。
- 上架 Chrome Web Store 或 Edge Add-ons 屬於對外動作，需使用者確認（記錄於 draft）；本 spec 只產生可安裝的套件。
- 外掛的介面文字沿用網頁版的繁體中文文字。
