# Feature Specification: 階段 3：PWA 與批次處理

**Feature Branch**: `005-pwa-batch`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "階段 3（不含上架商店與 Firefox 外掛）：PWA（離線、可安裝、出現在分享選單）與批次處理（一次處理多張圖，打包下載）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 離線也能用、可以安裝 (Priority: P1)

使用者第一次開啟網頁版後，之後即使沒有網路也能開啟並完整使用；也可以把它安裝成獨立的應用程式。

**Why this priority**: 「圖片不離開裝置」的自然延伸：連網頁本身都不需要網路（原則 1）。

**Independent Test**: 開啟網頁一次 → 斷網 → 重新整理 → 放入圖片、壓縮、複製、下載都能完成。

**Acceptance Scenarios**:

1. **Given** 使用者已經開過一次網頁版，**When** 在離線狀態重新開啟，**Then** 頁面正常載入，所有功能（含壓縮編碼器）可用。
2. **Given** 網頁版有新版本發佈，**When** 使用者在線上開啟，**Then** 背景下載新版本，並顯示「有新版本，重新整理以更新」，不會在使用者編輯途中強制重新整理。
3. **Given** 支援安裝的瀏覽器，**When** 使用者選擇安裝，**Then** 以獨立視窗開啟，有名稱與圖示。

---

### User Story 2 - 從其他應用程式分享進來 (Priority: P2)

已安裝的使用者在手機相簿或其他應用程式中選「分享 → TinyImg」，圖片直接在編輯器中開啟。

**Why this priority**: 行動裝置上沒有拖曳和貼上，分享選單是最短的路徑。

**Independent Test**: 模擬一次分享（以檔案送到分享目標），編輯器開啟該圖片。

**Acceptance Scenarios**:

1. **Given** 已安裝，**When** 從其他應用程式分享一張圖片給 TinyImg，**Then** 編輯器開啟並顯示該圖片。
2. **Given** 分享的是多張圖片，**When** 開啟，**Then** 進入批次模式（US3）。
3. **Given** 分享的不是圖片，**When** 開啟，**Then** 顯示明確的錯誤訊息。

---

### User Story 3 - 一次處理多張圖片 (Priority: P3)

使用者一次拖入或選擇多張圖片，全部以目前的設定壓到目標大小，看到每一張的結果，然後一次下載成 zip，或個別下載。

**Why this priority**: 常見情境是「把這次活動的 20 張照片都壓到 1 MB 再上傳」。

**Independent Test**: 放入 5 張測試圖片 → 全部完成 → 下載 zip → 解開後有 5 個檔案，大小都不超過目標（或被標示為無法達成）。

**Acceptance Scenarios**:

1. **Given** 使用者放入多張圖片，**When** 處理開始，**Then** 依序處理並顯示每張的狀態（等待中、處理中、已達成、無法達成、錯誤）與整體進度。
2. **Given** 全部完成，**When** 使用者按「全部下載（zip）」，**Then** 下載一個 zip，內含每張的結果，檔名不重複。
3. **Given** 其中一張是損毀的圖片，**When** 處理，**Then** 該張標示錯誤，其他照常完成，zip 不包含失敗的那張，並在畫面上清楚列出。
4. **Given** 批次處理中，**When** 使用者點選其中一張，**Then** 在單張編輯器中開啟該張（可以再編輯、標註）。
5. **Given** 批次處理中，**When** 使用者按「取消」，**Then** 停止處理尚未開始的圖片，已完成的仍可下載。

---

### Edge Cases

- 批次中有同名檔案：zip 內自動加上序號（例如 `photo_compressed (2).jpg`）。
- 一次放入超過 100 張：仍可處理，但一次只處理一張以免記憶體不足；顯示總進度。
- 離線時的第一次造訪：沒有快取時無法離線使用（瀏覽器限制），顯示一般的離線錯誤即可。
- 快取版本更新時正在編輯：不強制重新整理，保留使用者的工作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 網頁版 MUST 在第一次載入後快取所有需要的檔案（含壓縮編碼器），之後離線可完整使用。
- **FR-002**: 有新版本時 MUST 在背景下載，並提示使用者重新整理；MUST NOT 自動重新整理。
- **FR-003**: 網頁版 MUST 可安裝（具備名稱、圖示、獨立視窗的設定）。
- **FR-004**: 已安裝的網頁版 MUST 能從系統分享選單接收一張或多張圖片。
- **FR-005**: 使用者 MUST 能一次放入多張圖片（拖曳、選擇檔案、分享），以目前的設定依序處理。
- **FR-006**: 每張圖片 MUST 顯示狀態與結果大小；整體 MUST 顯示進度；失敗的圖片不影響其他圖片。
- **FR-007**: 使用者 MUST 能下載所有成功的結果為一個 zip（檔名不重複），或個別下載。
- **FR-008**: 使用者 MUST 能取消批次，並能把任一張帶到單張編輯器。
- **FR-009**: 首次載入的程式碼 MUST 仍不超過 200 KB（壓縮後）；離線快取的檔案不計入。

### Key Entities

- **批次項目**：來源檔案、狀態、結果（或錯誤）。
- **快取版本**：與每次建置對應，新版本取代舊版本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 第一次造訪之後，離線重新開啟並完成「放入 → 壓縮 → 下載」的成功率為 100%（端對端測試）。
- **SC-002**: 批次處理 10 張 12 百萬像素以下的照片，全部完成的時間不超過單張時間總和的 1.2 倍。
- **SC-003**: zip 解開後的檔案數等於成功張數，檔名不重複，每個檔案的內容與單張下載完全相同。
- **SC-004**: 首次載入程式碼不超過 200 KB。

## Assumptions

- 分享目標只在已安裝的 PWA 中有效（瀏覽器限制）；未安裝時沒有分享選單項目。
- zip 使用不壓縮的 store 模式：圖片本身已壓縮，再壓縮幾乎沒有效益，也讓實作保持簡單。
- 批次一律使用目前的壓縮設定；個別調整請把該張帶到單張編輯器。
- 範圍外：自動上架商店（需要使用者的帳號）、Firefox 外掛（已否決，history/006）。
