# 對外發佈需要使用者確認

> 怎麼冒出來的：階段 0（specs/001-foundation）實作 CI/CD 時，部署這一步屬於對外動作，AI 不能自己決定。

## 待決定

1. **Push 到 GitHub**：目前所有工作都在本機的 `001-foundation` 分支上。push 之後才會觸發 CI。
   - 推薦：push 分支並開 PR，讓 CI 在 PR 上跑；確認全綠後再合併到 main。
2. **Pages 設定**：repo Settings → Pages → Source 必須改成「GitHub Actions」，`pages.yml` 才能部署。
   - 推薦：改成 GitHub Actions。也可以由 AI 用 `gh api -X POST repos/timcsy/tinyimg/pages -f build_type=workflow` 代為設定，但需要你同意。
3. **部署網址**：暫定使用預設的 `https://timcsy.github.io/tinyimg/`（Vite 的 `base` 為 `/tinyimg/`）。
   - 推薦：先用預設網址；之後如果要換自訂網域，只需要改 `base` 並加上 CNAME。
4. **actionlint 驗證**：AI 嘗試把 actionlint 安裝到暫存目錄（`go install`），被權限系統拒絕。目前只用 YAML 解析器確認過 workflow 的結構。
   - 推薦：你在本機執行 `brew install actionlint && actionlint`，或允許 AI 安裝。第一次 push 之後，CI 本身也會驗證 workflow 是否能跑。
5. **授權條款**：舊版 README 寫著「MIT License - 詳見 LICENSE 檔案」，但 repo 裡從來沒有 LICENSE 檔案。新版 README 暫時拿掉了這句。
   - 推薦：如果要用 MIT，加上 `LICENSE` 檔案（作者為 timcsy）。選授權是你的決定，AI 不代為決定。

## 不阻塞的部分

除了實際部署，其餘都已經在本機完成和驗證：workflow 檔、本機完整模擬 CI 流程、建置與測試。
