> 怎麼冒出來的：`/knowie-judge` 收尾階段 0 時，從實作過程（commit `8f3a893`、`f8615be`）整理出來。

## 候選 1：一個在舊實作下也會通過的測試，證明不了新實作

- **怎麼撞到的**：SC-002（PNG 截圖要能壓到 1 MB）的測試第一次就通過了。加上「必須用到量化或縮尺寸」的
  斷言後才發現，測試用的截圖在無損 PNG 時就已經小於 1 MB——舊版那個「PNG 品質參數無效」的實作
  也會通過這個測試。
- **解決方式**：讓截圖產生器加入漸層、內嵌照片和反鋸齒文字，使無損大小接近真實截圖；
  並保留 `neededWork` 斷言作為鑑別力的守門員（`packages/core/test/png.integration.test.ts`）。
- **教訓（判準）**：驗收測試要能讓「已知錯誤的實作」失敗，才算證明了什麼。
- **相關**：experience「勾選框記錄的是有人宣稱做完了，不是它能用」——同一族：通過的檢查不等於有效的檢查。
- **推薦**：固化。它會改變寫驗收測試的判準（每條驗收要問「舊版會不會也過？」）。

## 候選 2：沒有輸出的量測不是量測

- **怎麼撞到的**：用 `timeout 300 npx vitest ...` 量測量化耗時，指令失敗後我宣稱「image-q 超過 5 分鐘還沒完成」。
  實際上 macOS 沒有 `timeout` 指令（exit 127），量測根本沒有執行。後來重新量測，才得到真實數據
  （1 MP 需要 5.4 秒）。
- **教訓（判準）**：下結論之前，先確認量測真的跑了而且有產出；「失敗」和「沒執行」要分開看。
- **相關**：knowie 的「Answer to ground truth」不變式；原則 2。
- **推薦**：固化。

## 候選 3：在不完整的關卡下 commit，等於關卡不存在

- **怎麼撞到的**：commit `f8615be` 時，`npm test` 的 exit code 是 1（根目錄的 `node --test scripts/` 找不到測試檔），
  我先 commit 了，下一步才修。原則 4 寫的是「CI 全綠才算完成」。
- **教訓（判準）**：commit 前要跑的是**完整**的關卡指令，而不是剛改過的那一部分。
- **推薦**：考慮改成 git pre-commit hook 或 CI 檢查，而不只是寫成教訓；這是機制問題，不只是紀律問題。
